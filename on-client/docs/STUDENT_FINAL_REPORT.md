## 2. 핵심 3대 기능을 보여 주는 5단계 시연 순서 (Demonstration Scenario)

심판 및 평가자가 앱을 실행하고 핵심 3대 기능을 순서대로 검증할 수 있는 표준 시연 시나리오입니다.

### [1단계] 원클릭 앱 기동 및 퀵 내비게이션 확인
1. **명령어 실행**:
   - 방법 A (가장 추천): 프로젝트 루트의 **`run-bankhar-b.bat`** 파일을 더블클릭합니다.
   - 방법 B: 터미널에서 `npm run demo`를 입력하고 Enter를 누릅니다.
2. **화면 확인**:
   - 웹 브라우저가 자동으로 열리며 `http://127.0.0.1:5189`로 접속됩니다.
   - [현재 로그인] 바로 아래에 파란색 테두리의 **`[★ bankhar_b 핵심 3대 기능 우선 안내]`** 배너가 최우선으로 표시되는지 확인합니다.
   - 배너 안의 **`[⬇ 내 PC 상태 진단 영역으로 바로 이동]`** 버튼을 클릭(또는 Tab 후 Enter)하여 아래쪽 학생 진단 카드로 즉시 스크롤 이동하는 것을 확인합니다.

### [2단계] [핵심 기능 2] 내 PC 상태 진단, 다시 조회, 추이 비교 시연
1. **내 PC 상태 진단 카드 점검**:
   - **일반 권한 실측값 확인**: 네트워크 온라인 여부(`정상 연결`), RTT 대역폭(`50 ms`), 논리 코어(`12 Cores`), JS 힙 메모리(`~15 MB`), 브라우저 저장소(`~0.00 MB`)가 초록색 배지와 함께 측정 시각과 함께 표시되는지 확인합니다.
   - **확인 불가 항목 및 사유 확인**: 호스트 물리 IP/MAC, OS 전체 CPU 점유율(%), 전체 물리 RAM, 전체 C 드라이브, 방화벽 설정, Windows 이벤트 로그에 대해 `[확인 불가: 사유 명시]`가 정직하게 표기되는지 확인합니다.
   - **`[SDP 미연결]` 독립 카드 확인**: PC 로컬 조회가 성공한 것과 원천 SDP 서버 미연결 상태가 섞이지 않고, 주황색 경고 테두리의 `[SDP 미연결]` 카드로 분리 표시되는지 확인합니다.
   - **안내 문구 확인**: Windows 이벤트 통계 하단에 *"※ Windows System 및 Application 이벤트 기록 건수는 정상적인 운영체제 백그라운드 서비스 및 응용프로그램 동작 통계이며, 침해나 공격 탐지 결과가 아닙니다."* 문구가 명시되어 있는지 확인합니다.
2. **다시 조회 및 대기 표시 시연**:
   - 카드 우측 상단의 **`[🔄 내 PC 상태 다시 조회]`** 버튼을 클릭합니다.
   - 버튼이 비활성화되며 **`[조회 중… ⏳]`** 대기 인디케이터로 바뀌고 약 0.35초 후 최신 실측 스냅샷이 성공적으로 갱신되는지 확인합니다.
3. **직전 대비 추이 및 타임라인 퀵 필터 시연**:
   - 하단 [시각순 PC 상태 점검 기록 타임라인]에서 방금 재조회된 스냅샷이 최상단에 추가되고, 직전 측정값과 비교하여 **`메모리 추이: ▲ +0.12 MB 증가`** 또는 **`▼ 감소`** 문구가 자동 분석되어 표시되는지 확인합니다.
   - 3종 필터 탭(`[전체 점검 기록]`, `[네트워크·방화벽·Windows]`, `[CPU·메모리 자원]`)을 차례로 클릭하여 해당 카테고리 기록만 정확히 필터링되는지 확인합니다. (※ 설명용 예제 데이터는 완전히 제거됨)

### [3단계] [핵심 기능 1] 시각순 보안 사건 타임라인 및 거르기 시연
1. **타임라인 목록 확인**:
   - 화면 상단 [보안 사건 타임라인] 영역으로 이동합니다.
   - 최근 발생 시각 기준 내림차순(최신순)으로 정렬된 사건 목록을 확인합니다.
   - 각 사건마다 `[실측: 시스템 로컬]` (초록색)과 `[예시: 데모 가상 데이터]` (노란색) 배지가 명확히 부착되어 있는지 확인합니다.
2. **4종 퀵 필터 탭 시연**:
   - **`[전체 기록 (All)]`** 탭 클릭 ➔ 전체 시각순 사건 목록 복원.
   - **`[업무 앱 접속 (Access)]`** 탭 클릭 ➔ 업무 앱 접속 판정 사건(`kind === 'access'`)만 필터링.
   - **`[XDR 보안 경보 (XDR)]`** 탭 클릭 ➔ 비정상 행위 및 정책 위반 XDR 경보(`kind === 'xdr'`)만 필터링.
   - **`[접근 차단·경고 (Blocked)]`** 탭 클릭 ➔ 차단/거부 상태(`state.access === 'denied'`) 사건만 필터링.

### [4단계] [핵심 기능 3] 4단계 조치 상태 전이 타임라인 및 미연동 경고 시연
1. **4단계 타임라인 게이지 확인**:
   - 하단 [조치 제안 및 집행] 영역으로 이동합니다.
   - `[1. 제안]` ➔ `[2. 확인]` ➔ `[3. 접수]` ➔ `[4. 원천 확인]` 4단계 진행 게이지가 시각적 프로그레스 바로 표시되는지 확인합니다.
2. **원천 효과 분리 경고 확인**:
   - 게이지 아래에 주황색 배지로 **`⚠ 원천 집행 미연동 (SDP 원천 조치 미연결 상태)`** 문구가 명시되어, 백엔드 차단기가 실제로 동작하는 것처럼 속이지 않고 안전한 시뮬레이션 상태임을 나타내는지 확인합니다.

### [5단계] 완전한 키보드 접근성 시연 (Mouse-Free)
1. 마우스를 내려놓고 키보드의 **`Tab`** 키를 연속으로 누릅니다.
2. 초점이 이동할 때마다 고대비 노란색 테두리(**`outline: 3px solid #f5b400`**) 포커스 링이 선명하게 나타나는지 확인합니다.
3. 퀵 필터 탭과 **`[🔄 내 PC 상태 다시 조회]`** 버튼에 초점이 맞추어졌을 때 **`Enter`** 또는 **`Space`** 키를 눌러 마우스 없이도 정상 동작하는지 확인합니다.

## 3. 아직 안 되거나 ‘확인 불가’로 남은 한계 (4대 한계)

진실성과 투명성 원칙에 따라, 현재 단계에서 웹 런타임 제약이나 환경 미비로 인해 실제로 확인할 수 없는 항목들을 명확히 기록합니다.

| 한계 항목 | 현재 상태 | 상세 사유 및 사실 관계 | 안전 조치 및 대응 안내 |
| :--- | :---: | :--- | :--- |
| **1. OS 전체 하드웨어 자원 점유율** | **확인 불가** | 브라우저 샌드박스 보안 모델상 웹 JavaScript는 호스트 OS의 전역 커널 카운터(전체 CPU 사용률 %, 전체 물리 RAM 16GB, C 드라이브 전체 디스크 용량)를 직접 조회할 수 없습니다. | 브라우저 권한 실측치(논리 코어 수, JS 힙, 웹 스토리지)만 실측하고, OS 전역 수치는 「확인 불가」 및 사유를 정직하게 명시함. 데모용 예시치는 `[예시]` 배지로 엄격히 분리함. |
| **2. 방화벽 설정 및 Windows 이벤트 로그** | **확인 불가** | 일반 브라우저 환경에서는 Windows Defender 방화벽 정책 및 System·Application 이벤트 뷰어 API에 직접 접근할 권한이 없습니다. | **절대 방화벽 설정을 변경하려 하지 않고 읽기 시도만 수행**하며 「확인 불가」로 처리함. 통계 건수는 비침해 안내 문구와 함께 설명용 예시치로만 분리 제공함. |
| **3. 원천 SDP 서버 자동 집행기 연동** | **SDP 미연결** | 현재 에이전트는 로컬 시뮬레이션 데모 환경에서 실행 중이며, 실제 기업 백엔드의 원천 SDP Controller 및 게이트웨이 인프라와 네트워크 세션이 연결되어 있지 않습니다. | PC 로컬 조회 성공과 SDP 미연결을 섞지 않고 `[SDP 미연결]` 독립 카드로 분리하고, 조치 영역에 `⚠ 원천 집행 미연동` 경고 배지를 상시 부착함. |
| **4. 운영 앱 승인 서명 및 배포 런타임** | **담당자 준비 필요** | 사내 보안 운영 환경 전용 코드 서명 키(`OPERATIONAL_APP_SIGN_KEY`) 및 전용 런타임(`PROVIDED_RUNTIME_NOT_INSTALLED`)은 학생이 임의로 생성할 수 없는 인프라 요소입니다. | 우회 플래그(`--app-only-v1`)를 쓰지 않고, 운영 담당자의 승인 키 및 런타임 설치가 필요한 정규 절차로 기록하고 `npm run package-app` 기본 포장으로 무결성을 검증함. |

## 4. 실제로 확인한 근거 (Verification Evidence)

- **접속 주소**: `http://127.0.0.1:5189`
- **구동 환경**: Windows 11, Node.js v24.19.0, Google Chrome / Edge
- **검증 결과**:

  - `renderAction` 4단계 프로그레스 바 및 미연동 경고 배지 표시 완료.
  - 브라우저 개발자 도구 콘솔 오류 0건 (`Uncaught Exception: none`).
