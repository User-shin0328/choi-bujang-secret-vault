## 2. 고른 핵심 기능 3개
기록할 자리는 세 개입니다. 실제로 만든 기능만 적고 쓰지 않는 자리는 ‘해당 없음’으로 둡니다. 작동하지 않는 기능은 확인한 증상을 적고, 아직 확인하지 못한 기능은 ‘미확인’으로 남깁니다.
시작 틀에 있던 기능을 그대로 써도 됩니다. 제공된 부분과 직접 바꾸거나 추가한 부분을 나눠 적습니다.

### 핵심 기능 1
- 기능 이름: 시각순 보안 사건 타임라인 및 4종 퀵 필터 거르기 (`renderEvents`)
- 제공된 부분: 원시 보안 사건 및 접근 기록 배열 데이터를 단순 나열하는 기본 목록 렌더링 틀
- 내가 직접 개선한 부분:
  1) 최근 발생 시각 기준 내림차순(최신순) 정렬 및 발생 시각 배지 적용
  2) 실제 사건 필드(`kind`, `state.access`)와 일치하는 4종 원클릭 퀵 필터 탭 연동 (`전체 기록`, `업무 앱 접속(access)`, `XDR 보안 경보(xdr)`, `접근 차단·경고(blocked)`)
  3) 가독성 높은 카드 디자인(줄간격 1.8, 여백 14px) 및 키보드 고대비 포커스 링(`outline: 3px solid #f5b400`) 지원
- 실제 확인 결과: 브라우저(`http://127.0.0.1:5189`)에서 4종 필터 탭 클릭 시 해당 카테고리 사건만 실시간으로 즉시 필터링되어 목록이 갱신되는 것을 확인 완료함.
- 잘못된 입력이나 연결 실패 때의 동작: 사건 데이터가 비어있거나 배열이 아닌 경우 오류로 중단되지 않고 `[주의할 알림이 없습니다]` 및 빈 상태 안내 문구를 안전하게 렌더링함.
- 근거(개인정보를 지운 화면, 실행 기록, 상대 경로):
  - 소스 코드: `on-client/student/extension.mjs` (`renderEvents` 구현부)
  - 최종 보고서: `on-client/docs/STUDENT_FINAL_REPORT.md` (제2장 3단계 시연 순서)
  - 실행 화면: 상단 [보안 사건 타임라인] 영역 내 4종 탭 클릭 및 실시간 거르기

### 핵심 기능 2
- 기능 이름: 내 PC 자원·네트워크·방화벽 진단 및 직전 대비 추이 분석 (`renderStatus`)
- 제공된 부분: ZTNA 기기 규정 준수 상태(`compliant`/`noncompliant`), OSV 취약점 및 기본 diagnostics 조회 틀
- 내가 직접 개선한 부분:
  1) 관리자 권한 없는 일반 브라우저 권한 실측치 막대 바(Progress Bar) 및 원형 배지(Circular Badge) 시각화 (온라인 여부, 대역폭 RTT, 논리 CPU 코어 수, JS 힙 메모리 점유율, 웹 스토리지 용량)
  2) 브라우저 샌드박스로 인해 조회가 불가능한 항목(OS 전체 CPU 점유율, 전체 물리 RAM, 호스트 물리 IP/MAC, Windows Defender 방화벽 정책, Windows 이벤트 로그)에 대해 거짓 예시값 대신 「확인 불가」 및 상세 사유를 명시
  3) PC 로컬 환경 조회가 성공한 것과 원천 SDP 서버 미연결 상태를 섞지 않고 `[SDP 미연결]` 독립 분리 카드 및 뱃지 표기
  4) `[🔄 내 PC 상태 다시 조회]` 버튼 및 `[조회 중… ⏳]` 대기 인디케이터 연동
  5) 시각순 상태 점검 타임라인 & 직전 측정 대비 메모리 추이(▲ 증가 / ▼ 감소 / ━ 유지) 산술 차이 자동 비교 분석 기능
  6) 하단 4개 보조 점검 영역(알림, 기기, 세션, 도움정보 복사)을 2×2 반응형 카드 그리드(`pc-sub-grid`)로 정돈하여 세로 스크롤 대폭 감소
- 실제 확인 결과: 실측 지표들이 게이지 바 형태로 정확히 출력되며, `[다시 조회]` 버튼 클릭 시 0.35초 대기 인디케이터 후 스냅샷이 누적되고 하단 타임라인에 `▲ +0.12 MB 증가` 형태의 추이가 즉각 분석·표시됨을 확인 완료함. 하단 2×2 그리드에서 `[도움정보 복사]` 클릭 시 안전한 진단 JSON이 클립보드로 정상 복사됨.
- 잘못된 입력이나 연결 실패 때의 동작: 네트워크 단절 시 오프라인 상태로 즉시 감지 전환되며, API 조회 실패 시 확인 불가 및 사유 명시와 함께 `[다음에 할 일: 연결 점검 및 재시도 버튼 클릭]` 안내 박스를 표시함.
- 근거(개인정보를 지운 화면, 실행 기록, 상대 경로):
  - 소스 코드: `on-client/student/extension.mjs` (`renderStatus` 구현부)
  - 최종 보고서: `on-client/docs/STUDENT_FINAL_REPORT.md` (제2장 2단계 시연 순서 및 제5장 실측/확인불가 정리표)
  - 실행 화면: 중앙 [내 PC 상태 (보안·네트워크·자원 진단)] 대시보드 및 하단 2×2 그리드

### 핵심 기능 3
- 기능 이름: 4단계 조치 상태 전이 타임라인 게이지 및 원천 집행 미연동 경고 (`renderAction`)
- 제공된 부분: 세션 무효화 및 격리 조치 요청 버튼 틀
- 내가 직접 개선한 부분:
  1) 조치 집행 과정을 4단계 수평 게이지 바로 시각화 ([1. 제안] ➔ [2. 확인] ➔ [3. 접수] ➔ [4. 원천 확인], 완료 초록 / 진행 파랑 / 대기 회색)
  2) 실제 백엔드 SDP 원천 차단기가 연동되지 않은 상태를 숨기지 않고 `⚠ 원천 집행 미연동` 주황색 경고 배지 명시
- 실제 확인 결과: 조치 단계별 프로그레스 바가 선명하게 렌더링되며, 실제 기업 게이트웨이가 차단된 것처럼 가장하지 않고 안전한 시뮬레이션 상태임이 투명하게 명시됨을 확인 완료함.
- 잘못된 입력이나 연결 실패 때의 동작: 유효하지 않은 조치 단계 수신 시 기본 대기 상태로 안전하게 폴백(Fallback) 처리하며, 미연동 경고를 상시 유지함.
- 근거(개인정보를 지운 화면, 실행 기록, 상대 경로):
  - 소스 코드: `on-client/student/extension.mjs` (`renderAction` 구현부)
  - 최종 보고서: `on-client/docs/STUDENT_FINAL_REPORT.md` (제2장 4단계 시연 순서)
  - 실행 화면: 하단 [조치 제안 및 집행] 영역

## 3. 값의 종류 구분
화면에 보이는 값마다 아래 넷 중 어디에 속하는지 적습니다.
- 실제 조회(내 PC 실측 또는 서비스 API 결과와 출처·조회 시각):
  - 네트워크 온라인 여부 (`navigator.onLine` 실측: 정상 연결)
  - 네트워크 왕복 시간 및 대역폭 (`navigator.connection` 실측: 50 ms / 10 Mbps)
  - 논리 CPU 코어 할당 (`navigator.hardwareConcurrency` 실측: 12 Cores)
  - 브라우저 JS 힙 메모리 점유량 (`performance.memory.usedJSHeapSize` 실측: ~14.8 MB, 잰 시각 표기)
  - 브라우저 웹 스토리지 용량 (`navigator.storage.estimate()` 실측: ~0.00 MB)
  - 등록 기기 준수 상태 (`devices.data` 실측: 1대 등록, `compliant`)
  - 현재 검증 세션 상태 (`sessions.data` 실측: 1개 세션, `active`)
- 설명용 예시(실제 조회 결과가 아닌 값):
  - **해당 없음 (0건)**: 사용자 및 평가 요구에 따라 화면과 코드에서 일체의 설명용 데모 예제 데이터(가상 CPU/RAM/IP/방화벽/Windows 통계)를 완전히 제거하여 현재 화면에는 순수 실측값만 존재함.
- 미연결(예: SDP 서버에 연결되지 않은 항목):
  - 원천 SDP 제어 서버 (`[SDP 미연결]` 독립 카드로 분리 표기, 실제 사내 SDP 통제 인프라와 미연결 상태)
  - 원천 조치 집행기 (`⚠ 원천 집행 미연동` 주황색 배지로 분리 표기, 원천 차단기 미연동 상태)
- 확인 불가(읽지 못한 값과 그 이유):
  - OS 전체 CPU 점유율 (%) [이유: 웹 브라우저 샌드박스 보안 정책상 일반 권한 자바스크립트는 OS 커널 전역 성능 카운터 직접 조회가 차단됨]
  - OS 전체 물리 RAM 용량 [이유: 브라우저 샌드박스 정책상 호스트 물리 하드웨어 정보 접근 불가]
  - 호스트 물리 네트워크 IP/MAC/DNS [이유: 브라우저 보안 격리로 호스트 어댑터 ARP/라우팅 테이블 접근 차단됨]
  - Windows Defender 방화벽 정책 [이유: 일반 웹 환경의 OS 보안 설정 접근 제한, 절대 임의 변경 금지 원칙 준수]
  - Windows System / Application 이벤트 로그 건수 [이유: OS 이벤트 뷰어 직접 조회 API 부재]

## 4. 같은 최종 소스와 패키지, 다시 실행한 기록

- 필요한 연결·파일·사전 설치물: Node.js 22 이상, Git, 기본 브라우저 (Chrome, Edge 등)
- 최종 소스 커밋: `74b440c6dc0a1ef78745b715b6bee4325f2dcd80` (직전 코드 수정 커밋: `f2448a126749f6cb70d3f0d9c1c530a8256be428`)
- 실행 패키지 경로: `c:\Users\User\Desktop\sktaleph2\on-client` (매니페스트: `on-client/package-manifest.json`, 런처: `run-bankhar-b.bat`)
- 소스와 패키지가 같은 커밋에서 나왔는지: 확인 완료 (동일 커밋 `f2448a126749f6cb70d3f0d9c1c530a8256be428` 기반 패키징 검증 완료)
- 다시 실행한 명령: `npm run demo` (또는 `run-bankhar-b.bat` 더블클릭)
- 다시 실행한 시각(한국 시간): 2026-10-27 15:30:00 (KST)

- 운영 환경 멈춤 구분: 사내 전용 서명 키(`OPERATIONAL_APP_SIGN_KEY`) 및 전용 런타임(`PROVIDED_RUNTIME_NOT_INSTALLED`)은 학생이 임의로 생성할 수 없는 인프라 요소이므로, 임의 우회 플래그를 쓰지 않고 정규 기본 포장(`npm run package-app`)으로 무결성을 검증하고 운영팀 설치 필요 항목으로 구분함.

## 5. 처음 사용한 사람이 막힌 곳
다른 사람이 처음 써 본 관찰과 내가 직접 다시 실행한 확인을 나눠 적습니다. 다른 사람의 사용을 관찰하지 않았다면 ‘미실시’로 두며 가상 결과를 만들지 않습니다.
- 다른 사람의 첫 사용 관찰 여부: 미실시 (다른 사람의 직접 사용을 관찰하지 않음)
- 막힌 위치: 해당 없음 (미실시)
- 내가 보완한 것:
  1) `Missing script: "demo"` 문제 해결: 루트 디렉토리 `package.json`에 `demo` 및 `package-app` 프록시 스크립트를 추가하여 루트와 `on-client` 어디서나 원클릭 실행이 가능하도록 보완함.
  2) 세로 스크롤 과도 문제 해결: 내 PC 상태 하단의 4개 보조 점검 영역(알림, 기기, 세션, 도움정보)이 세로로 길게 늘어지던 것을 2×2 반응형 카드 그리드(`pc-sub-grid`)로 컴팩트하게 정돈하여 한눈에 들어오도록 개선함.
- 다른 사람이 보완 뒤 다시 따라 해 본 결과: 미실시
- 내가 직접 보완 뒤 다시 실행한 결과: 루트에서 `npm run demo` 실행 시 한 번에 브라우저가 열리고 2×2 그리드로 정돈된 화면이 깔끔하게 표시됨을 직접 확인 완료함.

## 6. 받은 도움과 내 선택
AI·강사·동료의 도움과 참고 자료를 숨기지 않고, 어떤 제안을 고르거나 바꿨는지와 그 이유를 적습니다. 이 파일은 개인 앱 기록이며 반 전체 결과를 모으는 자료는 아닙니다.
- AI에게 받은 도움: `extension.mjs` 모듈 분리, W3C 웹 접근성 고대비 포커스 링 스타일 구현, 2×2 반응형 카드 그리드 CSS 스타일링, `package-app.mjs` 자동 패키징 도구 작성 지원.
- 동료에게 받은 도움: 방어전 기본 프레임워크 템플릿 공유 및 로컬 테스트 환경 구성 정보 교환.
- 강사에게 받은 도움: Zero Trust 원칙상 로컬 PC 실측 성공과 원천 SDP 서버 미연결을 절대 혼동하여 표시하지 말아야 한다는 핵심 피드백 지도.
- 함께 한 내용과 내가 맡은 부분: 공통 프레임워크 기반 하에, 나는 `bankhar_b` 전용 3대 기능(사건 타임라인 거르기, PC 실측 및 추이 분석 대시보드, 4단계 조치 게이지 및 미연동 경고) 구현과 UI/UX 고도화 전체를 전담함.
- 참고한 자료: MDN Web Docs (Network Information API, Performance API, Storage API), W3C Web Content Accessibility Guidelines (WCAG 2.1).
- 그중 내가 고르거나 바꾼 것:
  - AI가 초기에 제안했던 데모용 가상 수치 표시 방식을 배제하고, 사용자 요청에 맞춰 모든 예제 데이터를 완전히 제거하고 오직 "순수 실측값"과 "확인 불가 사유"만 표시하도록 선택함.
  - 세로로 길게 늘어지던 4개 보조 진단 섹션을 2×2 반응형 카드 그리드로 통합하여 시인성을 높이도록 UI 구조를 직접 선택·수정함.

## 7. 외부 SaaS를 쓴 경우에만
쓰지 않았다면 비워 둡니다. 참고 자료 네 곳을 포함해 어떤 서비스도 가입이 필수는 아닙니다.
- 서비스 이름과 출처: Supabase (이전 3~4단계 인증 및 DB 실습 시 사용, 현재 10단계 클라이언트 에이전트 단계에서는 로컬 시뮬레이션 환경으로 추가 외부 SaaS 미사용)
- 통화: KRW
- 사용 기간: 방어전 실습 기간
- 실제 비용: 0원 (무료 티어 이용)
- 예상 비용: 0원

## 8. 남은 한계와 다음에 확인할 것
- 아직 안 되거나 확인 불가로 남은 것:
  1) 브라우저 샌드박스로 인한 OS 전역 커널 자원(전체 CPU 점유율, 전체 물리 RAM) 및 호스트 어댑터 정보(물리 IP/MAC) 직접 조회 불가
  2) Windows Defender 방화벽 정책 임의 변경 금지 및 일반 권한 읽기 한계
  3) 실제 운영 엔터프라이즈 SDP 게이트웨이 및 백엔드 차단기 인프라와의 미연결 상태 (`[SDP 미연결]`, `⚠ 원천 집행 미연동`)
  4) 운영 환경 전용 코드 서명 키 및 운영 전용 런타임 부재 (운영팀 사전 준비 필요)
- 다음에 확인할 것:
  - 향후 운영 백엔드의 원천 SDP Controller 및 차단기 게이트웨이 엔드포인트가 연결될 경우, mTLS 인증서를 통한 상호 인증 및 실제 격리/차단 조치의 원천 집행 흐름을 실측 검증할 예정임.
